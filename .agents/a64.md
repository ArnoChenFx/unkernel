# The AArch64 CPU (src/a64)

kwemu's guest CPU on this branch: A64, ARMv8.0-A user mode (EL0),
little-endian, FP and AdvSIMD, with the optional LSE atomics and crypto
extensions (Optional features, below); no SVE, pointer authentication or
MTE (their hint-space encodings, PACIASP, AUTIASP, BTI, XPACLRI, run as
NOPs). The contract is `include/kw_emu.h` (ABI 2): `struct kw_regs` is the A64
register file and `kw_run` the A64 run loop. Two layers: the reference interpreter (raw bits
to semantics, one instruction at a time; `run.runRef`), which is the
semantic oracle, and the decoded-op tier behind `kw_run` (Decoded-op
tier, below), which decodes blocks once into compact ops and runs
everything it has no op for through the reference interpreter, and a
JIT that compiles hot decoded blocks to wasm (JIT, below: every op
kind, the frequent `generic` ops inline, the rest as calls of the
reference interpreter). Keep each instruction's semantics in a function
that takes decoded operands (`dp_imm.addSub`, `dp_imm.bitfieldOp`,
`dp_reg.sdiv`, ...) so the tiers can call the same code.

## Layout

`decode.zig` routes each word by the Arm ARM's encoding tables to exactly
one group file; it is complete and needs no change when instructions are
added. Each group file owns its decode and semantics, exposes
`pub fn exec(s: St, inst: u32) Error!Exit`, and returns `ill(s, inst)` for
everything it does not implement.

## Conventions every group file follows

- **Exits.** `.next`: retired, the dispatcher adds 4 to pc. `.jump`: a taken
  branch that set `s.r.pc` (`jump(s, target)`). `.trap`: did not retire,
  pc unchanged (`ill`, `misaligned`, `breakpoint`; `syscall` retires). The
  run loop polls interrupts after every `.jump` and every 64 instructions.
- **Registers.** Register 31 is XZR or SP by operand: `xr`/`reg`/`setX`/
  `setR` for XZR forms, `xsp`/`regSp`/`setXsp`/`setRsp` for SP forms.
  `setR(s, sf, n, v)` zero-extends W results. V registers: `vq`/`setVq`
  (128 bits), scalar `setVd/Vs/Vh/Vb` zero the rest, `setVec(s, n, q, v)`
  zeroes the top half when Q = 0, `lanes(T, v)`/`fromLanes`/`lane`/
  `setLane`/`v128(lo, hi)` for elements.
- **No u128 shifts by a variable amount, no u128 multiply or divide**, and
  do not build `(x << 64) | x` from integers (LLVM turns it into a
  multiply): on wasm these are compiler-rt calls (`__ashlti3`, `__multi3`)
  that the kernel does not link. `test/a64-test.mjs` fails if `kwemu.o`
  imports any function. `fromLanes`/`v128` go through vectors and are safe.
  Do not copy arrays of 64 bytes or more by value either (`buf = f(buf)`, a
  returned `[8]u64`): without bulk memory LLVM emits a `memcpy` call for
  them. Fill such buffers in place through a pointer.
- **Flags.** `nzcv` holds N, Z, C, V in bits 31..28 (`N`, `Z`, `C`, `V`).
  `addWithCarry(sf, a, b, carry)` returns the result and the flags (pass
  `~b, 1` for subtraction), `nzLogic` for logical ops, `condHolds(nzcv,
  cond)`.
- **Operands.** `shiftReg(sf, v, type, amount)`, `extendReg(v, option,
  shift)`, `decodeBitMasks(N, imms, immr, immediate, datasize)` (null where
  the Arm ARM is UNDEFINED), `replicate`, `sextN`, `bits(inst, hi, lo)`.
- **Precise faults.** An instruction that faults or traps has no effect:
  load everything into locals first, write registers last. A single
  `load`/`store` (any width up to 64 bits, unaligned and page-straddling
  allowed) is all or nothing; for several stores call
  `probeWrite(s, va, len)` over the whole range first (`store128`, pairs,
  DC ZVA do). `checkAlign(s, va, size)` raises KW_EV_MISALIGNED (needed by
  exclusives and LDAR/STLR).
- **FP.** Use `fparith.zig` (scalar and AdvSIMD FP alike): pure functions
  of raw bits (`u32`, `u64`; `u16` in conversions) and the FPCR value that
  apply every Arm rule (NaN order and DN, FZ with IDC/UFC, tininess before
  rounding, AHP, saturating conversions) and OR FPSR bits into a `fl`
  accumulator; write `s.r.fpsr |= fl` once, after anything that can
  fault. Its header lists the API. Underneath, `fpu.Fmt(B)` (`fpu.F32`,
  `fpu.F64`) does the core arithmetic; common.zig's `fpRound`/`fpRaise`
  map its RISC-V view. fpu follows RISC-V, so code that calls it directly
  must add the Arm rules: NaN operands propagate unless FPCR.DN
  (`processNaN`, `processNaNs`, `processNaNs3`, call before the
  arithmetic); Arm detects tininess before rounding, fpu after (UFC
  differs for results that round up to the smallest normal); FPCR.FZ
  (flush denormals, IDC) and AHP are not modelled by fpu. Linux starts
  tasks with FPCR = 0.
- **Optional features** (`Feature`, the `KW_ISA_*` bits: AES, PMULL, SHA1,
  SHA2, CRC32, LSE, SHA512, SHA3; `consistentIsa` drops SHA512 from a set
  without SHA2, so `kw_set_isa` never enables it alone). Decode a feature's encodings behind `has(s, .aes)`,
  else `ill`; add it to `common.implemented` only when it is complete and
  tested, because `kw_set_isa` then enables it and the kernel advertises it
  in AT_HWCAP. Implemented: all of them (Crypto and CRC32, LSE atomics).

## System registers and hints

What EL0 sees is Linux's EL0 view (arm64 Linux 7.x, `cpufeature.c`), so
kwemu answers everything an arm64 kernel would let through or emulate, and
the kernel never has to decode an MRS.

- Read and write: TPIDR_EL0, NZCV (bits 31..28), FPCR (`FPCR_MASK`: AHP,
  DN, FZ, RMode; FZ16, the trap enables, Len and Stride are RES0 in
  ARMv8.0 without FP16 and trapping), FPSR (`FPSR_MASK`: QC, IDC, IXC..IOC).
- Read only (MSR ILLEGAL): TPIDRRO_EL0 (0, as Linux leaves it for native
  tasks), DCZID_EL0 (4: DC ZVA allowed, 64-byte blocks), CTR_EL0
  (0x8444c004: 64-byte lines, IDC = DIC = 0, so software issues DC CVAU
  and IC IVAU for new code), CNTFRQ_EL0 (1 GHz, also what qemu reports),
  CNTVCT_EL0.
- CNTVCT_EL0 is the number of instructions this CPU has retired
  (`kw_cpu.icount` plus the current run): not wall time, and CPUs do not
  agree. The instruction returns `Hart.trap =
  .counter`; the run loop (`run.zig`) supplies the count through
  `branch.finishCounter` and counts it as retired. A decoded or JIT tier
  must do the same. The kernel must not base a vDSO clock on it.
- ID registers Linux emulates for EL0 (the HWCAP_CPUID space): MIDR_EL1
  (0x000f0000, implementer 0, so nothing picks core-specific code; qemu
  reports its own), MPIDR_EL1 (0x80000000, Linux's safe value), REVIDR_EL1
  (0), and op0 = 3, op1 = 0, CRn = 0, CRm = 2..7, any op2 (`idReg`): Linux's
  user view, i.e. visible fields describe kwemu and hidden fields show
  Linux's safe values. ID_AA64PFR0_EL1 = 0x11 (EL0/EL1 AArch64, FP and
  AdvSIMD without FP16), ID_AA64DFR0_EL1 = 6, ID_AA64MMFR0_EL1 =
  0x00000111ff000000, ID_AA64ISAR0_EL1 from the enabled features
  (`common.has`, so it follows `common.implemented` and kw_set_isa as
  AT_HWCAP does: AES 1, or 2 with PMULL; SHA1 1; SHA2 1, or 2 with
  SHA512; CRC32 1; Atomic 2 with LSE; SHA3 1), every other register 0 (no RDM,
  PAuth, SB, LSE2 (MMFR2.AT), ...; the AArch32 registers read 0 as on a
  kernel without 32-bit EL0). CRm = 1 and the rest of CRm =
  0 are ILLEGAL (Linux sends SIGILL; qemu also refuses the AArch32 ones).
- ILLEGAL: DAIF (SCTLR_EL1.UMA = 0), CNTPCT_EL0 and the timer registers,
  CNTVCTSS_EL0, RNDR/RNDRRS, PMU, debug (op0 = 2), SSBS, DIT, TCO,
  TPIDR2_EL0, every EL1 register.
- Hints (CRn = 2, Rt = 31) are all NOPs: WFE and WFI (Linux sets nTWE and
  nTWI, so EL0 does not trap; returning at once is a permitted wake-up),
  YIELD, SEV, SEVL, CSDB, the PAC hints (PACIASP, AUTIASP, XPACLRI, PACIA1716,
  ...), BTI, and unallocated hints (architecturally NOPs). MSR (immediate),
  CFINV/XAFLAG/AXFLAG, WFET/WFIT, and a hint encoding with Rt != 31 are
  ILLEGAL.
- Barriers: DMB and DSB (any option) are `c.barrier` (a full barrier on
  SMP), ISB nothing, CLREX closes the monitor. SB (FEAT_SB), DSB nXS,
  TCOMMIT and op2 = 0 are ILLEGAL.
- SYS (SCTLR_EL1.UCI and DZE set, as Linux does): DC ZVA (`dcZva`, all or
  nothing), DC CVAU, CVAC, CIVAC (a read probe: an unmapped address faults
  as on hardware, nothing else), IC IVAU (`icIvau`: no permission check).
  `icIvau` is the hook where decoded (and later compiled) code is dropped:
  `tier.icIvau` retires this CPU's blocks of the line's physical page,
  ends the running block, and bumps the code epoch every other CPU checks
  (Decoded-op tier, Coherence).
  DC CVAP/CVADP, the MTE forms and every EL1 operation are ILLEGAL, as is
  SYSL.
- Exception generation: SVC (any immediate) retires with KW_EV_SYSCALL;
  BRK raises KW_EV_BREAKPOINT; HVC, SMC, HLT, DCPS, ERET, DRPS, UDF and the
  PAC branches (BRAA, RETAA, ...) are ILLEGAL.

## Exclusives

`excl.zig`. The monitor is `Hart.resv` (address, `core.no_resv` when
closed), `Priv.excl_size` (bytes: 1..8, 8 for a W pair, 16 for an X pair),
`Hart.resv_val` (the value read; for a W pair the whole 64-bit word) and
`Priv.excl_val2` (the second register of a pair). kw_clear_reservation,
kw_set_pgd and CLREX close it. STXR/STXP pass only on exactly the same
address and size, and always close it; Ws = 0 on success, 1 on failure.
Every access must be naturally aligned (pairs: to the whole pair), else
KW_EV_MISALIGNED before anything happens. A store that would pass and
faults has no effect (the status register and monitor stay; the kernel's
trap return clears the monitor and the retry fails, so the guest loops).
The should-be-one fields (Rs, Rt2 where the form has none) must be 11111,
else ILLEGAL (the Arm ARM allows UNDEFINED for them). LDLAR/STLLR (LOR) are
ILLEGAL; CAS/CASP (LSE) are `lse.zig` (LSE atomics, below).

- One CPU: plain accesses; STXR stores when the monitor matches. A store by the same CPU in between does not close the monitor (the
  Arm ARM leaves that IMPLEMENTATION DEFINED; qemu compares values).
- `-Dkwemu-atomics` (`c.smp`): LDXR is a seq_cst
  atomic load, STXR a compare-and-swap against `resv_val` (another CPU's
  ABA store goes unnoticed, as in QEMU), LDAR/STLR seq_cst atomic
  load/store, which covers acquire/release. A W pair is one 64-bit access.
  Compiled code does the same with wasm atomics (JIT, Exclusives and
  atomics in compiled code).
- X pairs on SMP: wasm has no 128-bit compare-and-swap. LDXP is two 64-bit
  atomic loads; STXP (`storePair128Shared`) takes `pair_lock`, a word in
  kwemu's static data (global state, like the code epoch: all CPU threads
  share the linear memory; it is never held across an instruction, so
  parking and snapshots never see it taken), then compare-and-swaps the low
  half and the high half (undoing the low half if the high one changed).
  CASP of two X registers (lse.zig) takes the same lock, so every 128-bit
  write of an exclusive or atomic instruction is serialised by it.
  Guarantee: all 128-bit STXPs and CASPs are serialised, an STXP passes
  only if both halves still hold what the LDXP read (modulo ABA), so a
  torn LDXP never passes, and a CASP compares both halves inside the
  lock. Plain loads may see half an STXP or CASP, which ARMv8.0 allows
  (LDP is two 64-bit accesses). Not covered: a racing plain, 64-bit
  exclusive or 64-bit atomic store to one half while a 128-bit STXP or
  CASP runs. QEMU stops all other CPUs for this instead (or uses a host
  128-bit cmpxchg).

Tests: `src/a64/tests_excl.zig` (monitor rules, alignment, precise faults,
ILLEGAL neighbours, the 128-bit scheme on host threads, counter, ID
registers, masks, the ILLEGAL system space) and `guest/a64/atomictest.c`
(musl's a_cas/a_swap/a_fetch_add on LDAXR/STLXR, every size, 128-bit CAS
by LDAXP/STLXP, LDAR/STLR, register round trips, CNTVCT, DC ZVA, code
rewritten and made visible by DC CVAU + IC IVAU; compared with qemu).

Static corpus, the words of these groups that stay ILLEGAL: LDRAB (PAuth),
`mrs RNDR`/`RNDRRS`, `cbne` (FEAT_CMPBR), and two words the disassembler
shows as `ldxrh w29, [x18]` (0x484f565d) and `stlr w29, [x20]`
(0x888f969d) whose Rs and Rt2 are not 11111: data in the text section, no
assembler emits them.

## LSE atomics

`lse.zig` (FEAT_LSE, `KW_ISA_LSE`, HWCAP_ATOMICS, ID_AA64ISAR0_EL1.Atomic
= 2): LDADD, LDCLR, LDEOR, LDSET, LDSMAX, LDSMIN, LDUMAX, LDUMIN and SWP
(`size 111 0 00 A R 1 Rs o3 opc 00 Rn Rt`, routed from ldst.zig's single
register class: bit 24 = 0, bit 21 = 1, bits 11..10 = 00), CAS (from
excl.zig: o2 = 1, o1 = 1) and CASP (o2 = 0, o1 = 1, size 0x), every size
and A/L variant; ST<op> is LD<op> with Rt = XZR. ILLEGAL: all of it while
`.lse` is off; V = 1 (FEAT_LSFE), o3 = 1 with opc != 000 (LDAPR, ST64B,
LD64B, the RCW forms), CAS/CASP with Rt2 != 11111, CASP with an odd Rs or
Rt (UNDEFINED in the Arm ARM). Rs = 30 in CASP pairs x30 with XZR.

- Results: LD<op>/SWP write the old value, zero-extended to the register,
  to Rt; CAS writes it to Rs whether the compare passed or not (B and H
  forms compare and return only their bytes: Ws = ZeroExtend(data)); CASP
  writes Rs and Rs+1 (Rs is the lower address). Operands are read before
  anything is written, so Rs == Rt, Rn == Rs and Rn == Rt work.
- Alignment: to the access size (CASP: the whole pair), else
  KW_EV_MISALIGNED before anything happens. kwemu has no FEAT_LSE2
  (ID_AA64MMFR2_EL1.AT = 0); qemu's default `max` cpu has it and accepts
  unaligned atomics inside 16 bytes, so the qemu guest never tests that.
- Permission: every form needs write permission, also a CAS whose compare
  fails and an LD<op> into XZR (they are read-modify-writes for the MMU,
  as on hardware and in qemu-user, whose atomic helpers probe for write).
  So a CAS on a read-only page is KW_EV_FAULT with access WRITE (SIGSEGV
  from the kernel), and on a copy-on-write page it breaks the COW even
  when it does not store. The host pointer (`Cpu.rmwPtr`, which also
  tracks stores into decoded code) is taken before anything is read or
  written: a fault has no effect, no register is written.
- The exclusive monitor: an LSE store is a store like any other. One CPU:
  it does not close this CPU's monitor (plain stores do not either; the
  Arm ARM leaves it IMPLEMENTATION DEFINED). SMP: STXR is a compare-and-swap
  against what its LDXR read, so an LSE atomic of any CPU that changed the
  location makes it fail (ABA aside), as in qemu, whose STXR compares
  values too.
- Atomicity: one CPU needs nothing (kw_run never stops inside an
  instruction). `-Dkwemu-atomics` (`c.smp`): 1, 2, 4 and 8-byte forms are
  one seq_cst wasm atomic each (`rmwShared`: `.Add`, `.And` with ~Rs for
  LDCLR, `.Xor`, `.Or`, `.Xchg`; min and max are compare-and-swap loops,
  wasm has none; CAS is `@cmpxchgStrong`), which covers every A/L
  ordering. A W pair CASP is one 8-byte compare-and-swap; an X pair CASP is
  `casPair128Shared` under `pair_lock` (Exclusives, X pairs on SMP).
- Tiers: every LSE word is a `generic` op (the reference interpreter
  runs it); compiled code runs LD<op>, SWP and CAS inline (jit/atomic.zig,
  JIT, Exclusives and atomics in compiled code), CASP as a call. Measured
  on the image (State, below) they are far too rare to deserve op kinds.

Tests: `src/a64/tests_lse.zig` (encodings against the assembler; every
operation and size over edge-value pairs against an i128 reference, the
bytes around the access untouched; aliasing; CAS and CASP results; every

Mutation checks (2026-11-18, `zig build test` unless named): CAS B

## Crypto and CRC32

`crypto.zig`. AES, SHA1 and SHA2 decode in the crypto group, CRC32 and
CRC32C in data-processing 2-source (`dp_reg.twoSource` calls
`crypto.crc32`), PMULL/PMULL2 .1Q in AdvSIMD three different (simd_arith
calls `crypto.pmull64`, which is null while `.pmull` is not in
`implemented`, and must check `has(s, .pmull)` itself). Each instruction
checks its own feature bit, so `kw_set_isa` turns it into ILLEGAL; reserved
`size`/`opcode` values and CRC32 with the wrong `sf` are ILLEGAL too.

Nothing branches on or indexes memory by data (the timing does not depend
on keys or messages, as far as the host's integer multiply is
constant-time): SubBytes is the Boyar-Peralta 113-gate circuit, bitsliced
over the 16 state bytes (an 8x8 bit transpose per half), InvSubBytes the
same circuit between two affine maps; MixColumns works on packed bytes; the
carry-less multiply is `core.bitmanip.clmul`/`clmulh`; CRC32 folds each
input bit in with a mask (columns computed at compile time), no table.
core.aes's S-box tables (which the JIT's AES reads, AdvSIMD and crypto in
compiled code) are not cache-timing safe.

SHA-512 (FEAT_SHA512, `KW_ISA_SHA512`, ARMv8.2): SHA512H, SHA512H2 and
SHA512SU1 (`11001110 011 Rm 1 0 00 opcode Rn Rd`, opcode 00..10) and
SHA512SU0 (`11001110 11000000 100000 Rn Rd`), the Arm ARM's pseudocode on
the two 64-bit halves (FIPS 180-4's Ch, Maj and sigma functions; rotates
by constants, no data-dependent branch). The rest of the op0 = 1100
space other than SHA3 (below) stays ILLEGAL: O = 1 of the three-register
class (SM3PARTW1/2, SM4EKEY), SM4E, SM3SS1, SM3TT*, the reserved opcodes
(SM3 and SM4 have no `KW_ISA_*` bit; OpenSSL picks them only from
HWCAP_SM3/SM4). The architecture
has no SHA-512 without SHA-256 (ID_AA64ISAR0_EL1.SHA2 = 2 means both), so
`kw_set_isa` keeps SHA512 only together with SHA2: `kw.isa=-sha2` turns
both off, `kw.isa=-sha512` only SHA512 (SHA2 = 1), and `armv8,+sha512`
enables nothing.

A kernel advertises `KW_ISA_AES` as HWCAP_AES (ID_AA64ISAR0_EL1.AES >= 1),
`KW_ISA_PMULL` as HWCAP_PMULL (AES = 2), `KW_ISA_SHA1` as HWCAP_SHA1 (SHA1
= 1), `KW_ISA_SHA2` as HWCAP_SHA2 (SHA2 = 1), `KW_ISA_SHA512` as
HWCAP_SHA512 (SHA2 = 2), `KW_ISA_CRC32` as HWCAP_CRC32 (CRC32 = 1),
`KW_ISA_LSE` as HWCAP_ATOMICS (Atomic = 2), `KW_ISA_SHA3` as HWCAP_SHA3
(SHA3 = 1).

OpenSSL in the image takes its ARMv8.2 SHA-512 path when HWCAP_SHA512 is
listed, which the kernel does by default (`kw.isa=-sha512` turns it off).
Since the JIT translates SHA512H/H2/SU0/SU1 and the AdvSIMD ops around
them (vec.zig) that path is the fast one: `openssl speed -evp sha512`
217 MB/s against 131 on the integer path (2026-11-18, AdvSIMD and crypto
in compiled code). Before, it was all interpreter calls, 9.8 against 131
(12.5x slower), and the kernel left SHA512 off unless `kw.isa=+sha512`
asked for it; a host without wasm SIMD is back at that (10 against 122
MB/s), `--no-jit` about even (10 against 11). The digests agree with the
host's openssl both ways (guest-packages.md, Correctness).

SHA-512 tests: `crypto_tests.zig` (FIPS 180-4 "abc" and the two-block
message through the instruction semantics, driven as OpenSSL's
`sha512_block_armv8` drives them; gating with `kw_set_isa` and the SHA2
dependency with ID_AA64ISAR0_EL1.SHA2 = 2/1/0; reserved neighbours),
`cryptotest` against qemu (the same known answers, then one hash per
form, also with every operand the same register), kwtest (kernel.md).
The decode was compared with llvm-mc (`-mattr=+sha3`) over all of bits
23..10 of the `0xce` space with Rn, Rd in {0, 31} (65536 words): kwemu
accepts exactly the SHA512H/H2/SU0/SU1 words llvm-mc decodes as such
(2026-11-18). Mutation checks (2026-11-18, `zig build test`): Ch of
SHA512H with X's halves swapped and sigma1 shifting by 7 (the known-answer
unit test, cryptotest on every runner), SHA512 kept without SHA2 (the
dependency test), ID_AA64ISAR0_EL1.SHA2 = 1 with SHA512 (the dependency
and ID register tests): each caught.

SHA-3 (FEAT_SHA3, `KW_ISA_SHA3`, ARMv8.2): EOR3 (n ^ m ^ a) and BCAX (n
^ (m & ~a)) on 16 bytes (`11001110 0 Op0 Rm 0 Ra Rn Rd`, Op0 00 and 01;
10 is SM3SS1, 11 unallocated), RAX1 (n ^ rol(m, 1) per 64-bit lane; opcode
11 of the SHA512 three-register class) and XAR (ror(n ^ m, imm6) per
lane; `11001110 100 Rm imm6 Rn Rd`). Plain bit operations on whole
registers or 64-bit halves. SHA3 depends on no other bit here
(`kw.isa=armv8,+sha3` gives SHA3 alone).

OpenSSL does not use them on kwemu: its Keccak code takes the ARMv8.2
path only on cores it knows by MIDR_EL1 (Apple's, where it is worth it),
and kwemu's MIDR_EL1 is 0x000f0000 (implementer 0). Measured 2026-11-18
(same machine and method as SHA-512 above): `openssl speed -seconds 3
-bytes 16384 -evp sha3-256` 122.2-123.7 MB/s with SHA3 against
116.2-125.4 MB/s with `kw.isa=-sha3`, the same within noise (the ARMv8.2
path, all generic ops, would be several times slower, as SHA-512's is);
`openssl dgst -sha3-256` equals busybox `sha3sum -a 256` either way.

SHA-3 tests: `crypto_tests.zig` (SHA3-256 of "" and "abc" and SHAKE128 of
"" through Keccak-f[1600] built from the four instructions as OpenSSL's
ARMv8.2 code builds it, one state per 64-bit lane; edge cases of RAX1,
XAR #0/#1, BCAX; gating; reserved neighbours), `cryptotest` against qemu
(the same known answers, then per-form hashes of each instruction, XAR
with #0, #1, #37, #63, and aliased registers), kwtest (kernel.md). The
llvm-mc comparison above, with SHA3 implemented, matches exactly for
EOR3, BCAX, RAX1 and XAR too (2026-11-18). Mutation checks (2026-11-18, `zig build
test`): BCAX as n ^ (~m & a), RAX1 rotating right, XAR's high lane
using Vm's low lane (the Keccak known answers in the unit tests and in
cryptotest on every runner), ID_AA64ISAR0_EL1.SHA3 in the wrong field
(the ID register test): each caught.

## AdvSIMD arithmetic

Every ARMv8.0 instruction of the arithmetic classes, integer and FP,
vector and scalar, is implemented; v8.1+ (SQRDMLAH, DOT, FP16, FHM, FCMA,
FRINTTS, BF16, three same extra) is ILLEGAL. Each class decodes its
integer part and hands its FP part to one function in `simd_fp.zig` (the
doc comment of each lists its instructions), which decodes the rest
strictly (single and double; FCVTN/FCVTL also convert halves, with AHP).
PMULL/PMULL2 on 64-bit lanes call
`crypto.pmull64` behind `has(s, .pmull)`. Ops with one element size are
`simd_int.Op2` over lanes (`map2`; a by-element op is the same op with the
element broadcast as Vm); exact values are i128 for add, subtract and
compare only, shifts handle amounts of the element width and more on T.
Saturating ops set FPSR.QC.

FP lanes are `fparith.zig` calls with one `fl` per instruction (FPSR is
ORed once, at the end): `simd_fp.Bin` (two operands; FMLA/FMLS are
`mulAdd` with Vn negated for FMLS, FABD is `abs(sub)`, FACGE/FACGT compare
the absolute values) and `simd_fp.Un` (one operand: FRINT*, FCVT*, SCVTF,
UCVTF with fixed-point `fbits`, the estimates, compares with zero). Rules
that are easy to get wrong: FRECPS/FRSQRTS are fused (FRSQRTS computes
1.5 + a * (b/2), halving an operand whose exponent allows it, because 3 +
a*b may overflow where the result does not); the across-lanes reduction
is op(op(e0, e1), op(e2, e3)), so a signalling NaN quieted in the first
level loses to a number in FMAXNMV; pairwise ops pair the lanes of Vn,
then those of Vm; FCVTXN rounds to odd; a by-element index must not
select a lane of a u128 at run time (`c.lane` with a variable index
becomes `__lshrti3`), so `indexed` selects the 64-bit half with a mask.

Tests: unit tests in `simd_int.zig`, `simd_arith.zig` (every same-size
and two-reg misc op over all 8-bit operand pairs against a plain i128
reference, shifts over all counts, doubling multiplies on 16-bit
boundaries) and `simd_fp.zig` (estimate tables, known answers of the
steps, reserved encodings); `guest/a64/simdtest.c` enumerates every
non-register field of every integer form from its own legality tables
(6228 words) and hashes V0..V31 and FPSR over boundary-value register
states; `guest/a64/simdfptest.c` does the same for every FP form (1266
words) over 48 states of FP edge values and related operand pairs (tiny
products, a*b next to 2 and 3, FMLA cancellation), each with its own
FPCR (every RMode with FZ, DN, AHP) and some with FPSR bits preset, after
20 known answers (exit status = failures). `node test/a64-simd-fuzz.mjs
[--fp] [count] [seed]` (by hand) draws random words from the classes
(`--fp`: from their FP opcodes) and compares legality (classifier against
`qemu-aarch64 -cpu cortex-a53`) and results (simdtest `w` mode, or with
`--fp` simdfptest `w` mode with a new state seed per batch; native
harness, batches of 56 words). 2026-11-17: integer: 820000 words, 189582 run on both;
FP: see the State paragraph; no difference apart from PMULL 1Q while the
feature was off.

## Decoded-op tier

`kw_run` (`tier.run`) decodes guest code into blocks of compact ops once
and runs those; the reference loop (`run.runRef`) stays the oracle: unit
tests and the harness's `--lockstep` and `--ref` call it, and
`-Dkwemu-a64-ref` makes it kw_run (for a kernel to compare against).
Files: `ops.zig` (op format, kinds, decoder), `opexec.zig` (semantics,
`runOps`), `tier.zig` (block hooks, `run`, coherence), `tier_tests.zig`.

**Block cache.** One copy, ISA-neutral, in `src/emu/kwemu.zig`:
`Cpu.lookupIn(D, pc)` with the block table (2-way, 32K blocks, keyed by
virtual pc), exec-TLB generations, revalidation (same pc, same host
address, same raw words), the code-page filter with exact tracking of
guest stores (`code_flag` write-TLB entries), the op arena (a nursery
whose resets keep countdowns, and a tenured ring for compiled blocks'
ops: JIT, The op arena); `D` is the ISA's hook type (`tier.Blocks`:
`decode`, `validate`, `check` (pc alignment), `max_slots`). Everything
that reads a block's ops goes through `Cpu.opIndex(b.op)` (tenured ops
are numbered, not indexed). kwemu.md, Interpreter and Cache, describes
the machinery.

**Blocks.** Up to 64 instructions inside one page in execution order.
B.cond, CBZ/CBNZ and TBZ/TBNZ are side exits; B and BL to the same page
are followed (`b_f`, `bl_f`: the op stays, so the instruction count stays
exact, and BL's link is in the op). A block ends at BR/BLR/RET, a branch
to another page or to its own start, SVC, BRK, HVC/SMC/HLT, UDF and the
unallocated space, ISB, or the page end; a block that does not end in a
branch gets a `goto`. In the op arena a block's ops are followed by its
raw words, four per 16-byte slot, which `validate` compares: the raw word
is not in the op, which leaves eight bytes of fields.

**Ops.** 16 bytes: kind, seven field bytes a..g, a 64-bit imm. One
instruction is always exactly one op, so an op index is a count of
retired instructions, `pcAt` recomputes pc from the ops (pc + 4, or the
target of `b_f`/`bl_f`), and budget, icount and faults need no table
(op fusion was measured as no gain; kwemu.md, Rejected designs). Register
operands are slot indexes from `&regs.x`: 0..30 X, 31 SP, 32 XZR, 33
NZCV (low half), 35 TPIDR_EL0, 36 + 2n the low and 37 + 2n the high half
of Vn. Register 31 is resolved at decode time into SP or XZR. Slot 32 is
regs.pc, which holds 0 while ops run (`run` stores 0 before a block, a
`generic` op puts the real pc there for the reference and 0 back after,
and every way out sets pc), so XZR reads cost nothing. Only flag-setting
ops write slot 32 (a 0, through a write mask, for CMP/CMN/TST); a non-flag
op whose Rd is XZR decodes to `nop`, a load into XZR to `generic` (it
still accesses memory). Immediates are pre-decoded: bitmask immediates
expanded, shifts and negations folded, ADR/ADRP and literal addresses
absolute (literal loads are loads from slot 32 + address), MOVZ/MOVN/
MOV-bitmask constants, branch targets absolute, conditions as 16-bit
masks (bit i = the condition holds for NZCV = i).

**NZCV** stays architectural in regs.nzcv: every flag-setting op writes all
four bits, and a condition is one shift of its mask by NZCV. A 32-bit
operation computes its flags on its operands shifted left by 32 (one code
path for W and X: N, Z, C and V of the 64-bit sum are the 32-bit ones;
the carry-in of ADC/SBC goes in at bit 32). So every event leaves regs
exact without a materialisation step; lazy flags are the JIT's business (JIT, NZCV between alu.zig and its
consumers).

**Operand transforms without branches.** Shifted and extended register
operands are `((v << s1) >>a s2) & mask` (LSL, LSR, ASR, every
UXT*/SXT* with its shift), so one kind covers them; ROR operands of the
logical ops have their own kind. Bitfield moves are three shifts
(`ubfm`: shl, shr, shl; `sbfm` with an arithmetic shift and a mask; `bfm`
with the field mask), covering LSL/LSR/ASR immediate, UBFX, SBFX, UBFIZ,
SBFIZ, BFI, BFXIL and the extends. Variants of an operation are field
bits turned into masks (`0 -% bit`): AND/ORR/EOR, ADD/SUB, CSEL/CSINC/
CSINV/CSNEG, MADD/MSUB.

**Precise faults and multi-access instructions.** An op has no effect
when it faults: loads go to locals, registers are written last, in the
reference's order (writeback, then Rt, then Rt2). A pair or a Q access
checks the TLB once for its whole range when it lies in one page; else it
takes the reference's path (loads one after the other, the first fault
wins; stores probe the whole range first, then store through the path
that tracks stores into code). A fault leaves pc at the op (`pcAt`) and
refunds the rest of the block. A store that hits decoded code ends the
block after it (`.stop`), so self-modifying code runs the new
instruction next.

**Budget, interrupts.** `run` charges a block in full and refunds at a
side exit or an early exit; a block that does not fit the budget is
single-stepped through the reference interpreter. A block that branches
to its own start runs its further passes inside `runOps`, each charged
when the budget covers it. `*irq_pending` (and on SMP the code epoch) is
polled at every block end, also between self-loop passes: at least every
64 instructions, and at every taken branch out of a block (kw_emu.h; a
followed branch is not a poll point, which the reference loop's "after
every taken branch" was). MRS CNTVCT_EL0 is a `generic` op that returns
`.counter`; `run` supplies the count like the reference does.

**Generic ops** run `decode.exec` (the reference) on the raw word with pc
set (compiled code calls the same function: JIT, Generic ops in compiled
code). They are what has no op: system instructions (MRS/MSR other than
TPIDR_EL0, DMB/DSB on SMP, CLREX, DC, IC, ISB), exclusives,
load-acquire/store-release and LSE atomics, all FP and AdvSIMD data processing, the
AdvSIMD structure loads and stores, LDP of S/D registers, crypto and
CRC32, and every reserved or unallocated encoding (the reference raises
ILLEGAL). In qemu traces of ash, sort, gzip, gunzip and apk (2.3G
instructions) 0.58% of executed instructions are generic ops (UQSUB, DUP,
MOVI and other AdvSIMD in gzip, the crypto in apk's TLS, exclusives).
Optional features (AES, SHA, CRC32, PMULL, LSE) are generic only, so decoded
blocks do not depend on `kw_set_isa` (it resets the cache anyway, so
compiled code, which translates AES, PMULL and SHA only while their
feature is on, is dropped too).

### Coherence and several CPUs

One CPU: guest stores into decoded code are tracked exactly (kwemu.zig's
code-page filter: a store into a marked 64-byte chunk retires the page's
exec-TLB generations and ends the block), also through other virtual
aliases of the page, so self-modifying code takes effect at the next
instruction without IC IVAU. Writers the tracking does not see (the
kernel, another CPU) are covered by the flushes the kernel does on any
mapping change, which make every block revalidate against memory, and by
IC IVAU: `tier.icIvau` retires this CPU's exec-TLB entries that map the
line's physical page (cheap when the code-page filter says the page holds
no decoded code: the common case of new code), and ends the running
block.

Several CPUs: each has its own `struct kw_cpu`, so another CPU's store is
not tracked here. On hardware IC IVAU is broadcast. Here it also bumps
`code_epoch`, a u64 in kwemu's static data (shared by all CPU threads,
like excl.zig's `pair_lock`; atomic, seq_cst); every CPU compares it with
the epoch it last saw at kw_run entry and at every block end (beside the
`*irq_pending` poll) and, on a change, retires all its generations. The
CPU that bumps it stays current when it was. Guarantee: once IC IVAU has
retired on one CPU, every other CPU runs the new instructions from its
next block boundary, at most 64 instructions later, or at once if it is
not inside kw_run; no ISB is needed on the other CPU (the architecture
asks for one; a guest that omits it still works, as it does on hardware
in practice). The epoch exists only in atomics builds (and the unit
tests, which use two `kw_cpu` on one memory); a UP kernel pays nothing.
Cost on SMP: one atomic load (a plain load on x86-64) per block end, and
a full retire (512 exec-TLB entries, then one compare of raw words per
block used again) on the other CPUs per observed bump.

Alternatives: checking the epoch only at ISB and kw_run entry (context
synchronisation, what the architecture requires) lets a CPU that runs a
user loop without ISB keep stale code until its next kernel entry, up to
a budget slice per change. kwtest's `jit: code run on CPU 1, changed on
CPU 0` check runs such a loop (calls, no ISB, no syscalls): with no
cross-CPU invalidation at all it fails (751695 of 877496 calls stale,
2026-11-17; the ISB-and-entry variant was not built). A kernel broadcast (IC IVAU returning to the kernel,
which IPIs every CPU and waits, as the riscv64 guest's `flush_icache` did) needs a
new event kind (an ABI change) and costs an IPI round trip per IC IVAU;
JITs issue one per 64-byte line. Not done: a log of invalidated pages so
the other CPUs retire only those (worth it only if a guest that rewrites
code on one CPU slows the others measurably).

### Invariants (the tests check them)

- After every event (and with the same budget) registers, memory, event
  details and icount equal the reference loop's: `--lockstep` in the
  harness and the block fuzz compare them at every event.
- An op never executes partly: a fault leaves no register, writeback or
  memory change and pc on the instruction.
- A block runs only under the exec-TLB fill it was validated against;
  stores into decoded code end the block at once; IC IVAU on any CPU is
  seen within one block boundary on every CPU.
- The budget is never overrun and a self-loop never skips the poll.

## JIT

Hot decoded blocks are compiled to wasm by the ISA-neutral JIT core,
`src/emu/jitcore.zig` (kwemu.md, JIT tier: slot pool, compile policy,
`install` and its emit retries, regions, compile window, host contract;
all of it holds for A64), whose hooks `src/a64/jit/emit.zig` implements
(`C = jc.Jit(@This())`). `tier.run` enters the compiled code. It is built
with `-Dkwemu-jit` (wasm64 only), which kernel/build.sh passes by
default (`KWEMU_JIT=0` leaves it out). The emitted code depends only on
the decoded ops, pc and cpu-relative offsets, uses MVP instructions plus,
where the host compiles them (`kw_host_jit_caps` bit 5, `jc.cap_simd`),
fixed-width SIMD (a v128 local per V register; without it two i64), and
every module starts with the `cpu == 0` early return of kw_emu.h's
compile window.

Translated: every kind of alu.zig and bits.zig (moves, ADD/SUB and
logical in every form, the flag-setting forms with lazy NZCV, CSEL,
CCMP, ADC, bitfield, extract, variable shifts, multiply, divide,
RBIT/REV/CLZ/CLS), every load and store kind (mem.zig; Memory, below)
and every branch kind (branch.zig: side exits, conditional terminators,
followed branches, B, BL, BR/BLR/RET, `goto`), with self-loops and
regions. With SIMD, the integer AdvSIMD ops OpenSSL, musl, V8 and zlib
run, the vector loads and stores LD1/ST1, and AES, PMULL, SHA1, SHA256 and
SHA512 are inline too (vec.zig; AdvSIMD and crypto in compiled code,
below), and so are exclusives, LDAR/STLR and the LSE atomics but pairs
and CASP (atomic.zig, below). The other `generic` ops (FMA, AdvSIMD FP,
the rest of AdvSIMD without SIMD, system, exclusive pairs, CASP; scalar
FP arithmetic off its fast path) are calls of the reference interpreter where the host offers the
kernel's function table (Generic ops in compiled code, below); without it
they are handed back, and a block is compiled up to its first one.

### How compiled code runs (`tier.run`)

- `jit.C.ready` counts each pass of a block towards the threshold (2^17
  retired instructions; 1 with an eager host) and compiles the block,
  with the region gathered around it, once hot. A block counting down
  runs at most its countdown's worth of self-loop passes inside `runOps`
  (`cap`), so its next pass compiles it.
- `jc.enter` calls the module with `jl` = the budget left; it returns
  `(jl_left << 8) | code`. Done (`code >= jc.code_done`): pc is in
  regs.pc; a side exit at op k (`code_side + k`) refunds the rest of
  `jc.lastBlock` (a region's own side exits refund themselves and return
  `code_done_side`); then the interrupt poll and the epoch check of every
  block end, and `noteExit` (region growth along exits).
- Hand-back (`code < 64`): op `code` of `lastBlock` and the rest of that
  pass run through `runOps` from op k of the same decode. `run` stores 0
  into slot 32 first: compiled code writes pc there at every exit, and the
  ops read that slot as XZR. No further self-loop pass runs in `runOps`
  then (`cap = 0`): the next pass enters the compiled code again.
- Compiled code polls (`emit.zig` `poll`) at every self-loop back edge and
  checked member entry, where `run` cannot: `*irqp` (an
  `i32.atomic.load` on shared memory), and where several CPUs exist
  (`tier.multi_cpu`: atomics builds and the unit tests) the code epoch:
  `*a64.epoch_ptr` (the address of tier.zig's `code_epoch`, stored by
  kw_cpu_init and kw_host_reset because compiled code addresses memory
  only cpu-relative) against `a64.seen_epoch`, an `i64.atomic.load` on
  shared memory. Either stops the code at the block's start
  (`code_done_stop`); `run` then returns the interrupt or catches up with
  the epoch (retiring every generation) as at any block end. So a
  compiled loop on one CPU sees IC IVAU of another within one pass. A UP
  kernel's modules have no epoch poll.

### Register file and locals (`common.zig`)

i64 locals: 0..3 the parameters (x, cpu, irqp, jl), 4..7 the core's
(next pc, result code, data address, TLB entry), 8..11 region state, 12
NZCV, 13..20 `l_t` (scratch of one op's code, any family), 21..28
`l_alu`, 29..32 `l_br`, 33..36 `l_mem` (each family's own), 37..68
X0..X30 and SP (slot s: 37 + s), 69 TPIDR_EL0, 70 `l_vtmp` (the lane
value `cm.set` puts into a v128), 71..78 `l_u` (more scratch, vec.zig).
Without SIMD the V halves follow as i64 (79..142, slot 36 + j: 79 + j);
with SIMD a v128 group (79..110 V0..V31, 111..118 `l_q`, v128 scratch)
and an i32 group (119..134 `l_w`, i32 scratch). A module declares locals
only up to the highest index its code uses (each group's count is a
padded LEB patched after the body; a group needed after another makes
that one full), which is why the rare ones are last.

The prologue loads every slot the module's members read or write (a
hand-back writes every written slot back, also those the executed part
did not reach); the epilogue stores the written ones. V registers go by
whole register (both halves). NZCV is `i64.load32_u` / `i64.store32` at
regs offset 264: regs.nzcv is the low half of its slot and FPCR the high
half, which compiled code never touches. `cm.get(e, slot)` pushes a
slot's value (XZR: `i64.const 0`; a V half with SIMD: `i64x2.extract_lane`),
`cm.set(e, slot)` pops into it (XZR: dropped; a V half with SIMD:
`i64x2.replace_lane` through `l_vtmp`), `cm.setScalar` writes a V
register's low half and zeroes the high one, `cm.getV`/`setV`/`setVq`
move whole v128s (SIMD only), `cm.local(slot)` is an i64 local (not a V
half with SIMD). With SIMD the prologue, epilogue and the spills around
generic calls move V registers with one `v128.load`/`v128.store`.

### The family API

Each op kind belongs to exactly one family file (a comptime check in
emit.zig fails the build otherwise), and the families are owned by one
stream each:

| File | Kinds | Stream |
| --- | --- | --- |
| `alu.zig` | nop, movi, movk, mov, add/sub and logical (immediate, register, shifted, extended, ROR), the flag-setting forms, csel, ccmp, adc; the NZCV model | ALU and flags |
| `bits.zig` | ubfm, sbfm, bfm, extr, lslv/lsrv/asrv/rorv, madd, maddl, umulh, smulh, udiv, sdiv, rev1 | ALU and flags |
| `mem.zig` | every load and store kind (ldr*/str* _i/_w/_r, pairs, ldr_v, Q forms) | memory |
| `branch.zig` | side exits, terminators, b_f/bl_f, br/blr, goto; the region hooks `selfLoop`, `targets`, `memberTail`, `indirect` (complete for every kind) | branches and regions |
| `emit.zig`, `common.zig`, `kindtest.zig`, `tests.zig`, `jitcore.zig`, the JIT parts of `tier.zig` | hooks, dispatch, locals, test helpers | core |

A family file implements:

- `kinds`: the op kinds it owns.
- `supported(o: Op) bool`: whether this op is translated. The core
  compiles a block's ops up to the first unsupported one and hands that
  one back (the interpreter finishes the pass). Decide on fields if only
  some variants are done.
- `usage(o: Op) Use`: what the op reads and writes, from `cm.rd(slot)`
  and `cm.wr(slot)` (any slot: X/SP bits, V registers, TPIDR_EL0, NZCV;
  XZR gives nothing) combined with `.with(...)`, plus `.flags_read` /
  `.flags_write`. Exact usage matters: the prologue loads and the
  epilogue stores from it.
- `emit(e: *Emit, o: Op, at: At)`: the op's code; `at.k` is its index
  (instructions retired before it in the block), `at.pc` its pc, `at.b`
  the block, `at.self_loop` whether the block is being emitted as its own
  wasm loop.
- `Ext`: the family's part of the module's emission state (`e.x.alu`,
  `e.x.mem`, ...), `beginMember(e, ops)`: called when a block's or
  region member's code starts (reset per-member knowledge: a member can be
  entered from another member or from `run`), and `sync(e)` (see the
  NZCV contract).

What `emit` may do, with the core's `Emit` (jitcore.zig):

- Wasm: `e.op`, `e.ops`, `e.k64`, `e.k32`, `e.get`/`set`/`tee` (locals),
  `e.mem(opcode, align, offset)` with `e.addr()` before it (wraps an
  address for a memory32 kernel), `e.open(kind, type)`/`e.close()`,
  opcodes in `jc.W`.
- Hand back on a path: `e.handBack(at.k, at.pc)` leaves before the op
  (the interpreter runs it), so emit it before the op has written
  anything: compute into locals, write registers last.
- Memory: put the address in `cm.l_va`, then `e.tlbCheck(at.k, at.pc,
  jc.tlb_r_off or jc.tlb_w_off, size)` leaves the host address on the
  stack (a memory operand) or hands the op back on a miss (unmapped,
  straddling the page end, a page holding decoded code: `code_flag` in
  the write TLB), which keeps faults and SMC exact. One check covers a
  pair or a Q access in one page.
- Leave: `e.exit(target, jc.code_done)` (a terminator: falls through to
  the block's end, where a region continues at a member through
  `memberTail`), side exits `e.exit(target, jc.code_side + at.k)` +
  `e.brExit()` or, in a region (`e.rg`), `e.regionSide(rg, target, at.k,
  at.b)`; a self-loop's terminator `e.backEdge(at.b)` (poll, budget,
  charge, loop).
- Locals: `l_t` (8, scratch within one op), its own family range, the
  slots through `cm`.

Shared touch points, where two streams could meet: `Use` and `EmitExt`
(emit.zig) gain a field only through the core; a family needing more
locals or a module-level helper function (`helperCount`, `emitHelpers`:
none yet) asks the core; the optional core hook `syncHead` (emit.zig,
see the NZCV contract) is the one place the core gives a family a
different sync; `kindtest.zig`'s filler generators (`movi`,
`nop`, `dst`, `anyReg`, `base`, `sf`) are shared, a family keeps its own
generators in its own file; op field layouts (ops.zig) and semantics
(opexec.zig) change only with the tier. Nothing else needs a shared
edit: adding a kind touches only its family file.

### NZCV between alu.zig (producer) and its consumers

alu.zig owns the flags. The contract the others build on:

- `cm.l_nzcv` holds NZCV in bits 31..28 (as regs.nzcv) on every path that
  leaves straight-line code: the core calls `sync(e)` (emit.zig: each
  family's) before every exit, member transfer and self-loop back edge,
  and the epilogue stores l_nzcv when any op of the module has
  `flags_write`. Every exit and hand-back thus leaves regs.nzcv exact.
- A consumer asks `alu.cond(e, mask)` (pushes an i32: the condition with
  `ops.condMask` mask holds) or `alu.nzcv(e)` (the whole word as an i64);
  it never reads l_nzcv itself. Both push an expression and change no
  state and no local but their own, so they may be called on any path,
  also while the caller holds values in `l_t`.
- `sync` emits code only for the path it is called on and must not
  change the emit-time state of the path that continues.
- `alu.beginMember` starts every block and member with nothing known but
  l_nzcv.
- Before a branch back to the start of the block or member being emitted
  (a self-loop's back edge, `toMember` of the current member) the core
  calls the optional hook `syncHead` (emit.zig: alu's, then the other
  families' `sync`) instead of `sync`. alu.zig skips NZCV there when the
  block writes it before anything reads it or can leave (`head_dead`):
  l_nzcv is then stale at the loop head, which nothing can observe.

Lazy flags (alu.zig). A flag-setting op leaves A (its first operand) in
`l_alu + 0`, B in `l_alu + 1` (or as a constant in `e.x.alu.bk`: the
immediate forms, XZR) and the result R in `l_alu + 2`, W forms shifted
left by 32 as the interpreter computes their flags, and records in
`e.x.alu` what the flags are: NZCV of A - B (SUBS, CMP), of A + B (ADDS,
CMN), or N and Z of a logical R (ANDS, TST); CCMP/CCMN record the same
for their compare plus their condition in `l_alu + 3` and their default
NZCV. `cond` computes from that: CMP + B.cond or CSEL is one i64 compare
(EQ `a == b`, HS `ge_u`, GT `gt_s`, ...), MI/PL the sign of R, VS/VC and
the signed conditions after CMN from the overflow term, a CCMP chain a
`select` on its condition; ADC's carry is `cond(HS)`. NZCV is packed
into l_nzcv (about 20 wasm ops) only by `sync`, on the path that leaves,
or once right after a producer whose flags reach the end of its member
(no later flag write: the end is an exit or a hand-back anyway), which
saves a copy per exit path; not in a block compiled as its own loop,
whose back edge may skip them. A backward scan in `beginMember` marks
producers whose flags are overwritten before any read and before
anything that can leave (an op of another family counts as both): they
emit only their register result, or nothing (CMP, TST, CCMP). ADCS/SBCS,
whose carry in is not known at emit time, pack NZCV exactly. 11% of
executed instructions are B.cond, 10% flag-setting ALU ops.

### Worked example: adding `add_i`

`a = (b + imm) & (~0 >> d)` (ADD/SUB immediate, SP forms; ops.zig). In
alu.zig: `supported` gets `.add_i => true`; `usage` already says
`cm.rd(o.b).with(cm.wr(o.a))`; `emit` gets

```zig
.add_i => {
    cm.get(e, o.b);
    e.k64(o.imm);
    e.op(W.i64_add);
    if (o.d != 0) {
        e.k64(~@as(u64, 0) >> @intCast(o.d));
        e.op(W.i64_and);
    }
    cm.set(e, o.a);
},
```

and its test, at the bottom of alu.zig:

```zig
fn genAddI(r: std.Random) u32 { // ADD/SUB (immediate), any Rn/Rd incl. SP
    return 0x1100_0000 | kt.sf(r) | (r.uintLessThan(u32, 2) << 30) | (r.uintLessThan(u32, 2) << 22) |
        (r.uintLessThan(u32, 4096) << 10) | (kt.anyReg(r) << 5) | kt.anyReg(r);
}
test "a64 jit alu: add_i" {
    try kt.kind(.add_i, kt.one(genAddI), .{});
}
```

`kt.kind` (kindtest.zig) runs 200 programs of 24 such words (then SVC;
`Opt` changes counts, budget, seed) from edge and random register
values on a kw_run machine and on the reference loop and compares event,
icount, every register and all memory; in the wasm64 unit tests the
kw_run machine compiles every block on its first entry, and the test
fails unless some `add_i` op was compiled (so it cannot pass vacuously);
natively it checks the tier. A generator may write several words (a
setup sequence) and gets the pc of the first. The block fuzz
(tier_tests.zig) already makes every ALU, memory and branch form; a kind
it does not make needs a template in its `gen`.

### Memory (mem.zig)

Every load and store kind is translated: `ldr*`/`str*` `_i`/`_w`/`_r`
(all sizes, zero and sign extension to W and X, STR B/H/S/D), the pairs
with LDPSW and STP S/D, `ldr_v` (LDR B/H/S/D, literal included), and the
Q forms (LDR/STR/LDP/STP Q as two i64 per register). Each op computes its
address into `l_va` (literal: the absolute address in the op), then one
`tlbCheck` over the whole access (a W pair 8 bytes, an X pair or Q 16,
LDP/STP Q 32), then plain wasm loads and stores at the host address (the
second and further elements by offset immediates; the host address is
kept in `l_mem`, widened back to i64 on a memory32 kernel, where
`tlbCheck` leaves an i32). Shared memory changes nothing: the tier's fast
path takes plain host accesses too.

- Handed back before anything is written: every data-TLB miss (unmapped,
  no permission, a page not in the TLB yet, a straddle, also one that
  wraps past 2^64), an LDP/STP Q whose 32 bytes cross a page end (the
  interpreter then does two 16-byte accesses), and stores into a page
  holding decoded code (code_flag), which the interpreter stores and
  tracks (the block ends there).
- Register writes keep the reference's order (writeback, Rt, Rt2). Past
  the check nothing can fail, so only coinciding registers matter: a
  writeback whose base is also a loaded register is left out (the loaded
  value wins), Rt2 is written after Rt (LDP with Rt == Rt2), store data is
  read before the writeback (STR Xn, [Xn], #8 stores the old base).
- Module bytes, counted from the emitter: about 70 per single access (address 8, `tlbCheck` 55 with
  its hand-back, the access 5), a pair or Q about 12 more per further
  element.

Tests: one kind-test line per kind in mem.zig, each run twice (200
programs, budget 3000): from empty data TLBs and with kindtest's
`warm_tlb` (the data TLBs of every mapped page filled first), plus four
store kinds with `rwx_code` (the code pages writable: stores into decoded
code). The generator of each kind makes all its variants (sizes,
extensions, W/X and B..Q data, every addressing mode, literals) and sets
the base by ADR (a `movi` op) so the access lands where it wants: inside
the RW pages, at page ends, straddling two RW pages (the interpreter does
it, the JIT must hand back), straddling into the unmapped page, the
read-only page, the code pages, unmapped, wrapping past 2^64, page 0;
index registers by MOVZ/MOVN (UXTW, SXTW, LSL, SXTX, negative and W-sized
values); Rt now and then the base or the index, Rt2 = Rt, store data XZR.
One group in eight closes a loop (B to the program start), so the block
becomes a compiled self-loop whose later passes hit the TLB. Without the
loops and `warm_tlb` the kind tests only ran the miss path (a program's
first access to a page always misses) and caught only the first of the
mutations below.

### Generic ops in compiled code (emit.zig, `generic`)

What the tier runs through the reference interpreter is not handed back
any more: compiled code calls `opexec.jitGeneric(x, cpu, raw, pc)` with
`call_indirect` through the kernel's own function table, which the
module imports as `env.table` (funcref, table64 unless the kernel was
lowered). The host says it passes the table with bit 4 of
`kw_host_jit_caps` (`jc.cap_table`; js/core/jit.ts and
test/kwemu-jit-host.mjs set it); without that bit generic ops are not
`supported` and are handed back as before (`jc.table_ok`, set by every
CPU's `askHost`). jitGeneric has the type of a compiled function (four
i64, an i64 result), so no other import or export is needed.

- Around the call: lazy NZCV is materialised and every register slot the
  module writes is stored (its prologue usage, which the core keeps in
  `Emit.use`); after it the module's register locals are stale (the op
  may write any register, NZCV, FPCR, FPSR) and are loaded again before
  the next op of a family runs, or on any exit path (`sync`), so a run of
  generic ops spills and reloads once (`EmitExt.stale`). NZCV is exact
  after the call (`alu.exactNow`).
- Results: 0 retired; 1 not executed (a fault or trap leaves no effect,
  MRS CNTVCT_EL0 needs the count): the op is handed back and the
  interpreter runs it again, raising what it raises; 2 retired, and the
  block must end (a store into decoded code, IC IVAU; jitGeneric clears
  `smc`): a side exit to pc + 4 (in a region `regionSide`, which goes
  through the next member's checked entry).
- A block whose first op is generic is compiled now; what still hands
  back is data-TLB misses, stores into code pages and the results 1.
- The frequent ones are translated inline instead (`generic.zig`; they
  stay `generic` ops in the tier, and need no table): FMOV between
  general and FP registers (W/S, X/D, X/V.D[1]), UMOV, INS (general) of a
  64-bit lane, DUP (general), MOVI/MVNI (and FMOV vector immediate),
  AND/BIC/ORR/ORN/EOR (vector), MRS of FPCR, FPSR, NZCV and DCZID_EL0, and
  FCMP/FCMPE (single and double, register or #0.0), which hands back on
  a NaN operand or with FPCR.FZ set. They are what a stats kernel found
  most often (2026-11-18): busybox `seq`'s soft long double in musl's
  printf runs FMOV D/V.D[1], MRS FPCR, MOVI, MOV (vector) and FCMPE about
  30 times per number, musl's memset DUP, MOVI, MVNI and MRS DCZID_EL0.
  Generic ops still called, per command: `seq | gzip | gunzip` 0.72M
  (8.0M before), `seq | sort` 0.74M (2.76M; 0.40M of them the malloc
  lock's LDAXR/STLXR), an ash loop 0.41M (1.31M; the malloc lock and
  memset's DC ZVA). Bench (medians of 5 boots interleaved against calls
  only): gzip 2.30 to 2.02 s, ash loop 2.14 to 2.05 s, apk add jq 1.39
  to 1.32 s, the rest within noise.
- Scalar FP arithmetic and conversions are inline too, each with a fast
  path that is bit-exact with fparith.zig and the interpreter call on the
  rest (`fpFast`, `cvtz`): FADD, FSUB, FMUL, FDIV, FSQRT (single,
  double), SCVTF, UCVTF (W/X to S/D), FCVTZS, FCVTZU (S/D to W/X), FCVT
  (S to D, D to S); FMOV, FABS, FNEG (register), FMOV (immediate) and
  FCSEL need no slow path. The fast path needs FPCR.RMode = nearest and
  FZ = 0, and a result that is a normal number away from both ends of the
  range (no NaN, infinity, zero, denormal, overflow or underflow, so IXC
  is the only flag that can arise and wasm's result is Arm's); IXC is
  ORed into FPSR exactly: TwoSum for FADD/FSUB, the exact product in
  double for single FMUL/FDIV/FSQRT, the significant bits for SCVTF and
  UCVTF, a cut fraction for FCVTZ*. Double FMUL, FDIV and FSQRT need an
  exact product (an FMA, which MVP wasm lacks), so they take the fast
  path only while FPSR.IXC is already set (as soon as any inexact result
  happened). FCVTZS/FCVTZU do all of toFixed inline (NaN to 0, saturation,
  IOC); only FZ calls. The slow path stores the operands the interpreter
  reads and loads what it writes, nothing else (these ops neither trap
  nor touch NZCV). The FMA forms (FMADD, ...) stay calls.
  Measured with the stats kernel's generic-call histogram (`tier.fpForm`,
  by FP form, in the tail of Stats.op_hist; it counts the interpreter's
  generic ops too): `node -e` summing to 1e7 made 39.9M calls (SCVTF
  19.8M, FCVTZS 9.9M (V8's "is it a small integer" check of a double
  past 2^31: out of range, saturating), FADD 9.9M), now 0.1M; the
  `Math.sqrt` loop 18.3M (FMUL, FSQRT, SCVTF 3M each, FCVTZS, FADD), now
  0.07M. Time (UP bundle, medians of 3 boots): the sum 4.43 to 3.75 s,
  the sqrt loop 2.39 to 2.09 s (on top of the op arena change).
- Module bytes: about 6 per register slot stored and loaded, plus about
  30 for the call; over the bench boot 3541 modules, 23.7 MiB (3462,
  22.8 MiB before).
- `kwemu-jit.o` is checked for imports (a64-test.mjs): an emission state
  that grew past about 64 bytes was initialised with a `memcpy` call,
  which the kernel does not link (a trap at its first compile). The
  module's usage is therefore a pointer in the core's `Emit`.

Measured 2026-11-18 (the bench of Where apk's time goes, UP bundle,

### Exclusives and atomics in compiled code (atomic.zig)

The exclusive class, LDAR/STLR and the LSE atomics are `generic` ops in
the tier and inline in compiled code (emit.zig decodes them after
generic.zig's forms): LDAR, STLR, LDXR, LDAXR, STXR, STLXR (B, H, W, X),
LD<op> and SWP (every size and operation), CAS (every size), CLREX, DMB
and DSB (SMP builds: `c.barrier`'s seq_cst read-modify-write of
Hart.fence_word; on one CPU the tier makes them `nop`), ISB (nothing: the
block ends after it and `run` checks the code epoch) and DC ZVA. Pairs (LDXP, STXP, LDAXP, STLXP) and CASP stay interpreter calls
(no measured workload runs them). The LSE forms are translated only
while the compiling CPU has FEAT_LSE enabled (kw_set_isa drops compiled
code anyway).

- **Semantics** are excl.zig's and lse.zig's, field for field: LDXR opens
  the monitor in `struct kw_cpu` (Hart.resv = va, Hart.resv_val = the
  value, Priv.excl_size = bytes, Priv.excl_val2 = 0), STXR stores only
  when resv == va and excl_size == bytes, closes the monitor either way
  and writes Ws last, CLREX closes it. The kernel's clears
  (kw_clear_reservation at every switch and exception return, kw_set_pgd)
  write the same fields, which compiled code reads from memory each time.
- **Faults**: a misaligned address (`va & (size - 1)`) and every data-TLB
  miss hand the op back before anything is written. Everything that may
  store takes the write TLB (code pages carry `code_flag` there, so a
  store into decoded code goes back to the interpreter, which tracks it):
  STLR, STXR (also when its monitor does not hold: the interpreter then
  fails it without touching memory, the same result), LD<op> into XZR and
  a CAS whose compare fails (read-modify-writes need write permission,
  LSE atomics), DC ZVA over its whole aligned 64 bytes.
- **One CPU** (no `-Dkwemu-atomics`): plain wasm loads and stores; a
  module never stops inside an op, so every op is atomic.
- **SMP** (`c.smp`: the interpreter's semantics depend on the build, not
  on whether the host memory is shared): every access is a wasm atomic,
  as the interpreter's builtins compile: LDAR/LDXR `i64.atomic.load8_u`
  .. `i64.atomic.load`, STLR `i64.atomic.store*`, STXR an
  `i64.atomic.rmw*.cmpxchg` against resv_val (masked to the size; wasm
  also wraps a narrow expected value), CAS one cmpxchg, LDADD/LDCLR (AND
  with ~Rs)/LDEOR/LDSET/SWP one `i64.atomic.rmw*` each, the min and max
  forms a compare-and-swap loop from an atomic load (`rmwShared`). All
  wasm atomics are seq_cst, which covers every acquire/release variant;
  another CPU's interpreter or compiled code works on the same words with
  the same instructions, so no update is lost in any mix. V8 accepts
  atomic instructions on a memory that is not shared (the wasm64 unit
  tests of an atomics build), and the host address is naturally aligned
  (aligned guest address, page-aligned host page), as wasm atomics need.
  DC ZVA stays eight plain 8-byte stores, as the interpreter's.

### AdvSIMD and crypto in compiled code (vec.zig)

Where the host compiles fixed-width SIMD (`kw_host_jit_caps` bit 5,
`jc.cap_simd`, `jc.simd_ok`; js/core/jit.ts sets it after
`WebAssembly.validate` of a small v128 module), the V registers are v128
locals (Register file and locals, above) and vec.zig translates the
AdvSIMD and crypto `generic` ops that OpenSSL, musl, V8 and zlib run
(generic.zig's forms are decoded first). They stay `generic` in the tier;
without SIMD, and while an op's feature is off for the CPU (kw_set_isa:
`vec.enabled` reads `a64.isa` of the CPU that owns the emit buffer,
`Emit.cpu()`), they are interpreter calls as before. The decode routes by
`decode.route` and then takes each group file's own masks and legality
rules, so it accepts only words the reference runs with exactly that
meaning.

- **Lane ops.** Three same (ADD, SUB, CMEQ, CMTST, CMGT, CMGE, CMHI,
  CMHS (64-bit unsigned compares with the sign bits flipped: wasm has no
  unsigned i64x2 compare), [SU]MAX, [SU]MIN, MUL, MLA, MLS, URHADD,
  USHL/SSHL by register on S and D lanes (lane by lane in i64: wasm shifts
  take one count; B and H lanes stay calls); the scalar D forms of ADD,
  SUB, USHL/SSHL and the compares), pairwise ADDP/[SU]MAXP/
  [SU]MINP (evens and odds by two shuffles), ADDP (scalar), across lanes
  (ADDV, [SU]MAXV, [SU]MINV by halving shuffles), two-reg misc (CNT, NOT,
  ABS, NEG, the compares with zero), shift by immediate ([SU]SHR, [SU]SRA,
  SHL, SLI, SRI (bitselect under the lane mask), [SU]SHLL(2), SHRN(2);
  the scalar D forms; a right shift by the element size, which wasm would
  take modulo, is folded at decode), three different ([SU]MULL, [SU]MLAL,
  [SU]MLSL by extmul; [SU]ADDL, [SU]SUBL, [SU]ADDW, [SU]SUBW), by element
  (MUL, MLA, MLS, [SU]MULL, [SU]MLAL, [SU]MLSL with the element
  broadcast), BSL/BIT/BIF (bitselect), ORR/BIC (immediate), SMOV, INS
  (general) of B/H/S lanes.
- **Permutations.** UZP, ZIP, TRN, EXT, REV16/32/64, DUP (element, vector
  and scalar), INS (element), XTN(2) and SHRN(2)'s packing are one
  `i8x16.shuffle` each; the indices of UZP/ZIP/TRN and EXT come from
  `simd_move.permuteOp`/`ext` run at decode on numbered bytes, so they
  are the reference's by construction. TBL/TBX: `i8x16.swizzle` per
  table register on the index minus 16 j (swizzle gives 0 from 16 on,
  which is TBL's rule), TBX a bitselect under index < 16 n.
- **Loads and stores.** LD1/ST1 (multiple structures, 1-4 registers),
  LD1/ST1 of one lane, LD1R, LDP/STP/LDNP/STNP of S, D and Q registers:
  one TLB check over the whole access (else handed back: a miss, a page
  end, a store into a code page), then v128 loads and stores (`load64_zero`,
  `load*_lane`, `load*_splat`, `store*_lane`); the writeback last. mem.zig's
  Q forms use `v128.load`/`v128.store` with SIMD too. LD2-LD4/ST2-ST4 stay
  calls.
- **AES.** Table lookups in `jc.AesTab` (cpu-relative, filled from
  core.aes by `jitcore.init`; `mc` added for AESMC): AESE/AESD do
  AddRoundKey and leave the state pending in a v128 scratch (`vec.Ext`);
  the next op, if it is AESMC (AESIMC) of that register into itself, does
  (Inv)ShiftRows, (Inv)SubBytes and (Inv)MixColumns as one T-table round
  (per column four i32 loads of `te`/`td` rotated by row and XORed); any
  other op first writes the pending register (S-box bytes, through
  `i8x16.replace_lane`), and so does every path out of straight-line code
  (`vec.sync`, called first by emit.zig's `sync` and `syncHead`; a member
  starts with nothing pending). Nothing can leave between the two ops of a
  pair (both are translated, neither faults), so the fused pair is exact.
  A lone AESMC/AESIMC uses the `mc`/`im` tables the same way. Unlike the
  interpreter's bitsliced AES (Crypto and CRC32), the tables are indexed by
  data, as the riscv64 guest's compiled Zkne was: the compiled path is not constant-time
  on the host.
- **PMULL/PMULL2 .1Q:** Karatsuba over the 32-bit halves, each 32x32
  carry-less product core.bitmanip's multiply-and-mask sequence (16
  `i64.mul`; a column has at most 8 terms, so nothing carries into the
  next column of its class, and a 64-bit product of 32-bit operands is
  exact).
- **SHA:** SHA1C/P/M and SHA256H/H2 run their four rounds on i32 locals
  (`l_w`), renaming the state words instead of moving them; SHA512H/H2 on
  i64 locals; SHA1H, SHA1SU0/SU1, SHA256SU0/SU1, SHA512SU0/SU1 are lane
  operations on v128 (rotates as two shifts). RAX1, EOR3, BCAX, XAR stay
  calls (OpenSSL does not use them here, Crypto and CRC32).

### Generic ops by word (stats kernel)

A `-Dkwemu-stats` kernel also counts `generic` ops by instruction word
(`kwemu.countGenWord`, `JitStats.gen_words`): 512 open-addressed entries
of three words, the key (the word with Rd and Rn cleared, | 1 << 32), its
executions (interpreter and compiled code alike) and of those the calls
from compiled code; the last entry takes what finds no free entry. It
travels with the rest of the counters (`kw_debug_stats`, `KwemuStats.words`

### The op arena (2026-11-18)

How node's startup used the arena before (stats kernel, `npm --version`,
497M instructions per command): the 384K-op arena filled every ~10M
instructions (53 resets per command), and each reset freed every module
and zeroed every countdown, so 78% of the instructions ran interpreted in
blocks counting down. At each reset 84% of the arena was still live
(about 12K blocks in 270K of the nursery's 320K slots; a decode takes
about 22 slots, and npm decodes once per ~480 instructions): node's
working set is larger than the arena, so compaction would free little.
What is kept now (kwemu.md, Cache):

- A nursery reset keeps every block's table entry (pc, host, countdown;
  its ops are `op_gone`), and a re-decode of the same pc and host goes on
  counting. Compiled blocks' ops are in the tenured ring, so their code
  survives.
- The block table replaces the way with less countdown progress
  (`jitcore.victim`); the survivor loses half its progress. Without this,
  keeping countdowns made npm slower (6.04 against 5.22 s, one boot):
  conflict evictions dropped 420M charged instructions of progress per
  command, and region members evicted and decoded again failed their
  checked entry 1.16M times per command (each a return to `run`); with it
  165K, and 64M of progress lost.
- The tenured part is a ring: a plain area that freed every module when
  full made short apk commands 10-15% slower (`apk add --simulate git`
  0.76 against 0.70 s: about 450 modules freed per command).

Compiled share (stats kernel, one boot): `npm --version` 21% to 44%, `npx
--version` 22% to 43%, `node -e 0` 56-58% to 62-65%, `apk search` 75% to
80%, `apk add jq` 73% to 76%; per npm command 59-68 nursery resets, about
1.4K tenured blocks dropped by the ring (most compiled). Time (UP bundle,
guest seconds, medians of 3 boots interleaved): `npm --version` 5.18 to
4.91 and 4.61 to 4.39, `npx --version` 4.66 to 4.30, `node -e 0` 0.82 to
0.79, the JSON loop 4.99 to 4.81; the apk/shell bench (medians of 5)
within noise (sum of 20 rows 24.40 to 23.66 s). Compiled share goes up
more than time goes down: what the countdown kept compiles code that runs
a few thousand times per command, where entries, exits and recompiles
take much of the gain (npm enters compiled code every 55 instructions,
against 125 before).

Marking decoded code: every decode marks its 64-byte chunks in the
code-page filter (kwemu.zig, markCode), and used to scan all 1024
write-TLB entries whenever it added a chunk to a page; the scan is only
needed when a page becomes marked (a marked page's write-TLB entries are
flagged already), so more chunks of a marked page now skip it. Node
decodes about a million blocks per npm command: `npm --version` 4.95 to
4.56 s, `npx --version` 4.34 to 4.01, `node -e 0` 0.78 to 0.70 (medians
of 3), the apk/shell rows 9.52 to 9.35 s (medians of 5, sort 2.86 to
2.71); lookupSlow was 12% of npm's busy host time, mostly that scan.
A slot of the filter (4096 of them, by host page) that two pages share
is wild: it marks every page that hashes to it. Until 2026-11-18 every
mark of a wild slot scanned the write TLB again: about 300K scans per
`npm --version` (stats kernel; 86% of all scans), since node's code
spans far more pages than the filter has slots. Now a slot scans when it
changes state only: when it becomes wild, or gets bits again after
stores cleared them all, every entry of every page that hashes to it is
flagged (later fills see the slot as marked). Test: `a64 tier: stores
into code of pages that share a wild mark slot` (three code pages 16 MiB
apart, a writable alias whose write-TLB entry predates the marks);
mutations caught: the wild transition scanning only its page, the slot
scan matching only the page. Time (UP bundle, guest seconds, medians of
3 boots interleaved): `npm --version` 4.46 and 3.94 to 4.19 and 3.75,
`npx --version` 3.96 and 4.00 to 3.82 and 3.71, `node -e 0` 0.77 and 0.69
to 0.72 and 0.67, the JSON loop 4.46 to 4.33, Bun (`bun -e` x10) 0.73 to
0.70, `bun run t.ts` x5 0.91 to 0.86; the apk/shell rows (medians of 5)
22.65 to 22.66 s.

The counters (`-Dkwemu-stats`, `tier.Ar`, in the unused tail of
Stats.op_hist): nursery resets and what was live at each, tenured blocks
and slots, decodes by what the table way held (the same block with its
ops gone, other contents, another host, another block, nothing),
countdown progress taken over, tenured blocks dropped. Countdown progress
is in charged instructions (a pass charges the whole block, also when a
side exit leaves early), which is why "lost" progress could exceed the
instructions run.

### Exit costs (2026-11-18)

Priced by doubling one piece in a throwaway build and timing it against
the build without (UP bundle, guest seconds, medians of 7 boots

code of a stats kernel; per command): an exit to `run` or a hand-back,
a self-loop's or member's own back edge, a branch to another member, right
after a producer whose flags reach its member's end ("eager"), before an
interpreter call. `seq | sort`: 9.0M exit, 3.8M back edge, 17.3M member,
54.4M eager; gzip 16.2M, 26.4M, 8.9M, 14.7M; the ash loop 3.8M, 1.7M,

29.7M. The eager site is the biggest: a member whose last flag write
reaches its end materialises once there, for every path out.

### What is left

- ALU and flags (alu.zig, bits.zig), memory (mem.zig) and branches and
  regions (branch.zig) are translated (above).
- `generic` ops are inline (generic.zig; with SIMD also vec.zig) or
  calls of the interpreter (above).
- The compiled share on the image (2026-11-18, stats kernel, per
  command, with the op arena change): 76-86% for apk update, search, info

  sort` and `seq | gzip | gunzip`; `npm --version` 44%, `node -e 0` 63%,

  threshold; hand-backs left are data-TLB misses (0.1-0.5%).

Next levers, by measured remaining cost (2026-11-18):

1. Cold code in node and Bun: `runOps` itself (41% of npm's busy host
   time; its code size matters, Decoded-op tier, Numbers) and the `run`
   loop (14%). Chaining interpreted blocks inside `runOps`, a bigger exec TLB
   and a 16 MiB `KW_CPU_SIZE` did not pay (Rejected designs (A64)); a
   lower threshold lost before (2^15: npm 5.93 against 4.86 s). Left:
   smaller handlers for the frequent kinds, cheaper decodes (10%; first
   decodes of a new process cannot be shared while ops hold absolute
   addresses), tier op kinds for LDAR/STLR/LDXR/STXR (1.2M interpreted
   generic executions per npm command, 9-10M in cowsay; generic ops are
   about 1.5% of npm's host time).
2. `run`'s entry path and the region prologue: about 5% of the apk/shell
   rows each (Exit costs). Inlining `jc.enter` into `run` changed
   nothing. Lighter prologues need a region-wide "written before every
   exit" analysis (the light entry, loading only the entered member's
   registers, was slower on the riscv64 guest; kwemu.md, Rejected designs).
3. NZCV materialisation: about 3% of the same rows; the eager site after
   a member's last producer is the largest. Carrying lazy state across
   member transfers needs a runtime kind for the checked entry's stop
   path; at most part of the 3%.
4. Generic calls left (stats kernel, calls from compiled code per
   command, 2026-11-18): FMADD (busybox `seq`, 0.25M in the gzip row,
   89K in sort; an exact fused result without a wasm FMA needs the
   emulated FMA of fparith.zig inline, worth at most about 2% of that
   row), and in OpenSSL LD4/ST4 and RAX1-type SHA3 ops that it does not
   run here. Exclusives, LDAR/STLR, LSE, barriers, DC ZVA and loads into
   XZR are inline (Exclusives and atomics in compiled code). AdvSIMD
   and exclusives in node run mostly in cold code (1-8M and 1-10M
   interpreted executions per command).
- A back-edge or checked-entry budget test off by one is caught only as
  a hanging test, not as a failed assertion.

Risks: the lazy-flags model (members of a region must see exact NZCV:
`sync` before every transfer); V8 compiles bigger modules (more locals,
Q halves) more slowly than the riscv64 guest's; the 16 KiB emit buffer may cut A64
regions sooner (measure module bytes per block as kinds land).
